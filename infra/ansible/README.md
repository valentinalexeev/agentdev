# agentdev on GKE: Ansible (#11, phase 2)

Installs the webhook router and the agents onto the cluster from `infra/terraform`. It renders the **same**
`manifests/*.tmpl` files the kind scripts use, so local and GCP stay in step.

## Prerequisites
- Terraform applied (`infra/terraform/README.md`), and `$(terraform -chdir=../terraform output -raw get_credentials)` run.
- The worker image pushed to Artifact Registry and `worker_image_tag` set (CI does this later).
- Secret values in Secret Manager (added by you or the management UI #12, never by Ansible):

| Secret | Value |
|---|---|
| `claude-shared` | `KEY=VALUE` lines: `CLAUDE_CODE_OAUTH_TOKEN=...` or `ANTHROPIC_API_KEY=...` |
| `router-register-token` | random string (`openssl rand -hex 32`) |
| `github-app-webhook-secret` | the GitHub App's webhook secret (#2) |
| `agent-<name>-forge-token` | the agent's forge token (until #2 mints GitHub App tokens) |
| `agent-<name>-claude` | optional; the agent's own Claude credential (`KEY=VALUE`) |

`agent-<name>-wake-token` is generated by the playbook on first run.

## Run
```bash
cd infra/ansible
ansible-galaxy collection install -r requirements.yml
ansible-playbook deploy.yml --check --diff     # dry run
ansible-playbook deploy.yml -e worker_image_tag=<tag>
```
Settings live in `group_vars/all.yml` (project, region/zone, agents, forge). Secret values are read at run
time and every task that handles one uses `no_log`.

## Not here
GitHub API support in the worker and the public webhook Ingress come with #2; the cutover is phase 4 of #11.
Day-2 changes (adding agents, rotating credentials) move to the management UI (#12).
