# agentdev on GKE: Ansible (#11, phase 2)

Installs the webhook router, the agents, the platform namespace and (optionally) the management API onto the cluster from `infra/terraform`. It renders the **same**
`manifests/*.tmpl` files the kind scripts use, so local and GCP stay in step.

## Prerequisites
- Terraform applied (`infra/terraform/README.md`), and `$(terraform -chdir=../terraform output -raw get_credentials)` run.
- Images published on GHCR (#28): `ghcr.io/valentinalexeev/agentdev-worker` and `agentdev-router`; set `image_tag` to a release image tag (`0.1.0` for git tag `v0.1.0`) or `main`.
- Secret values in Secret Manager (added by you or the management UI #12, never by Ansible):

| Secret | Value |
|---|---|
| `claude-shared` | `KEY=VALUE` lines: `CLAUDE_CODE_OAUTH_TOKEN=...` or `ANTHROPIC_API_KEY=...` |
| `router-register-token` | random string (`openssl rand -hex 32`) |
| `github-app-webhook-secret` | the GitHub App's webhook secret (#2) |
| `github-app-private-key` | the GitHub App's private key (PEM, `.secrets/github-app/private-key.pem` from `scripts/github-app.sh convert`, #2) |
| `agent-<name>-forge-token` | only with `forge_kind: gitea`: the agent's forge token. On GitHub the sidecar mints App installation tokens |
| `agent-<name>-claude` | optional; the agent's own Claude credential (`KEY=VALUE`) |
| `agentdev-api-forge-token` | optional; token of the forge account `agentdev-api` for the API (#100, #104): scopes `read:repository,read:user` only, the account is admin of the agent repositories. Synced to the Secret `agentdev-api-forge` (`FORGE_API_TOKEN`) |
| `security-siem` | optional; SIEM output secrets as `KEY=VALUE` lines (#71): `SECURITY_WEBHOOK_SECRET`, `SECURITY_OTLP_HEADERS`, `SECURITY_SYSLOG_CA`, `SECURITY_SYSLOG_CLIENT_CERT`, `SECURITY_SYSLOG_CLIENT_KEY`, `SECURITY_OTLP_CA`, `SECURITY_OTLP_CLIENT_CERT`, `SECURITY_OTLP_CLIENT_KEY` (PEM on one line, `\n` for line breaks) |

SIEM addresses (not secret) go into `instance.yml` under `security.siem`: `webhook_url`, `syslog_addr`,
`syslog_server_name`, `otlp_url`, `otlp_server_name`. The playbook writes both into the Secret `agentdev-api-siem`, with the same keys as `.secrets/platform/siem-webhook` on kind
(table in `docs/admin.md`).

`agent-<name>-wake-token` and the platform secrets `platform-<key>` (Postgres and ContextForge passwords and keys,
the same keys as `.secrets/platform/` on kind) and `platform-pg-agentdev-api` (the API database login) are generated by
the playbook on first run.

## Platform (#51)
The `platform` role deploys Postgres and ContextForge from `manifests/platform.yaml.tmpl` into `platform_ns`,
then runs `scripts/mcp-sync.sh` for each spec in `mcp_projects` (paths on the operator machine; needs `yq`, `jq`,
`curl`). Only servers on hosts in `mcp_allowed_hosts` are registered (`docs/security.md` R51); the sync output is
not logged (`no_log`). The ContextForge admin password reaches the script as a 0600 temp file that is removed afterwards.
The platform NetworkPolicies are enforced because the Terraform cluster uses Dataplane V2; `docs/admin.md` has the check.
Overrides: `platform_postgres_image`, `platform_contextforge_image`, `platform_cf_admin_email`, `platform_service_cidr`
(must match the Terraform `services` range, `roles/platform/defaults/main.yml`).
On a first `--check` run the platform secrets do not exist yet, so the diff shows empty passwords; the real run
creates them first. The same holds for the API: a first `--check` without `platform-pg-agentdev-api` renders
`agentdev-api-db` with an empty password (hidden by `no_log`). An optional secret (`agentdev-api-forge-token`,
`security-siem`) that exists without an enabled version counts as absent. Other roles that need a platform password (for example the API database login, once the API is deployed on GKE) read `platform-<key>`
from Secret Manager and run after `include_role: platform`.

## Management API (#104)
The `api` role runs after `platform` when `instance.yml` sets `api.oidc_issuer` (an `https://` URL; authentik on GKE
is #114, so any OIDC provider with a public client `agentdev` and a `groups` claim with `agentdev-admins`). Like
`./run.sh 10` it:
- creates `agentdev_owner` (NOLOGIN, owns database `agentdev` and its objects) and the login `agentdev_api`, applies
  `images/api/schema.sql` as the owner, sets the retention (`api.db_retention_days`, default 365) and applies
  `images/api/grants.sql`. SQL goes to `psql` in `platform-db-0` on stdin (`no_log`), never in argv;
- writes the Secrets `agentdev-api-db`, `agentdev-api-forge` (only if Secret Manager `agentdev-api-forge-token` has
  a value, else absent: forge writes give 503, fail closed) and `agentdev-api-siem` (addresses from
  `security.siem.*`, secret values from `security-siem`; the same keys as `.secrets/platform/siem-webhook` on kind,
  table in `docs/admin.md`); restarts the API when one changes;
- applies `manifests/api.yaml.tmpl` and waits for the rollout.
Other keys: `api.oidc_discovery_url`, `api.oidc_audience`, `api.forge_url`, image override `api_image`
(`roles/api/defaults/main.yml`). Secrets come from `tasks/secrets_gcp.yml` (`api_secret_source: gcp`); a local
source for kind is a new `secrets_local.yml` that sets the same facts when `run.sh` moves to Ansible (#106).
The API checks permissions on Gitea only (#87); with `forge_url` on GitHub only `agentdev-admins` can change agents.

## Public HTTPS entry point (#120)
The `ingress` role runs last when `instance.yml` sets `ingress.host`. It applies one GKE Gateway
(`gke-l7-global-external-managed`) on the Terraform static IP (`ingress.static_ip_name`, default `agentdev-webhook`)
with the Terraform Google-managed certificate (`ingress.certificate`) and SSL policy (`ingress.ssl_policy`). Routes:
`https://<webhook_host>/hook` to `webhook-router`, `https://<host>/` to `agentdev-ui` (only when the UI is deployed,
that is with `api.oidc_issuer`), port 80 redirects. HSTS on every HTTPS response; Cloud Armor
(`ingress.security_policy`) on both backends when set. Values come from `terraform output ingress`. The role stops
when the cluster does not serve the Gateway API (Terraform `gateway_api_config`). Render test:
`tests/ingress_render.yml`. The `api` role now also applies `manifests/ui.yaml.tmpl` (`api.ui: false` skips it).

## Run
Usually the deployment repository's CI runs this (template `examples/deployment/gcp-gke`). By hand:
```bash
ansible-galaxy collection install -r infra/ansible/requirements.yml
ansible-playbook infra/ansible/deploy.yml -e @<deployment repo>/ansible/instance.yml --check --diff   # dry run
ansible-playbook infra/ansible/deploy.yml -e @<deployment repo>/ansible/instance.yml
```
`group_vars/all.yml` holds only generic defaults. Instance values (`gcp_project`, `gcp_zone`, `image_tag`,
`reviewer`, `agents`) come from the deployment (`example.vars.yml` shows the shape); the playbook stops with a
clear message if one is missing. Secret values are read at run time and every task that handles one uses `no_log`.

## kind (#106)
The numbered shell steps (`run.sh`, `0*.sh`, `1*.sh`) are deprecated. They move to `kind.yml` one step per PR, each
with a kind e2e that proves parity (two runs on a fresh kind cluster, the second must report `changed=0`; run by
hand and reported in the pull request until a CI job does it); the old step stays as a wrapper that prints a
deprecation notice and calls the playbook, for one MINOR release. Ported so far:

| run.sh step | `kind.yml` tag | Role |
|---|---|---|
| 01 | `cluster` | `kind_cluster` |

```bash
ansible-playbook infra/ansible/kind.yml --tags cluster    # kind cluster, gVisor, RuntimeClass, smoke test
```
The role takes `kind_cluster_name`, `kind_cluster_engine`, `kind_cluster_gvisor_version` and `kind_cluster_config`
(the wrapper passes the values of `config.env`). It is idempotent: a second run reuses the cluster and the installed
gVisor. The role always downloads the `.tar.bz2` archive of gVisor and checks its sha512 (the old step used
`.tar.zstd` when `zstd` was installed).
